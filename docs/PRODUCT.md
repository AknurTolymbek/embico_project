# EMBICO Platform — Описание продукта

**Версия документа:** 1.0
**Дата:** 03.11.2024
**Источник:** Анализ embico-demo.html

---

## 1. Обзор платформы

EMBICO — клиническая информационная система для клиники ЭКО (репродуктивная медицина). Платформа ведёт полный клинический путь цикла экстракорпорального оплодотворения от первичной консультации до исхода беременности.

**Ключевые характеристики:**
- Интерфейс на русском и казахском языках
- Роли: репродуктолог и эмбриолог
- Полная история пациентки (все циклы, результаты)
- Интеграция с ML-моделями для прогнозирования
- Синтетические данные для разработки и демонстрации

## 2. Структура приложения

### 2.1. Главное меню (навигация)

**Основная навигация (main-nav):**
1. **Рабочий день** (Today) — очередь задач и активные циклы
2. **Пациенты** (Patients) — реестр пациенток
3. **Циклы** (Cycles) — все циклы ЭКО
4. **Лаборатория** (Lab) — эмбриологические данные
5. **Эмбрионы** (Embryos) — реестр эмбрионов
6. **Документы** (Documents) — протоколы циклов

**Служебная навигация (utility-nav):**
- **Команда** (Team) — пользователи и роли
- **Настройки** (Settings) — конфигурация системы

### 2.2. Экраны приложения

#### **Рабочий день (viewToday)**

**Назначение:** Главный экран для ежедневной работы врача/эмбриолога.

**Разделы:**
- **Очередь задач** — задачи, требующие внимания сегодня
  - Просроченные (красный цвет)
  - Запланированные на сегодня
  - Фильтр: «Мои задачи» / «Все задачи»
- **Активные циклы** — карточки текущих циклов (до 3 шт.)
  - Пациентка, ID цикла, текущий этап
  - Дата начала, назначенный врач/эмбриолог
- **Сводка:**
  - Количество активных пациенток
  - Задачи, требующие внимания
  - Запланированные задачи

**Действия:**
- Открыть задачу (переход к соответствующему разделу цикла)
- Создать новую пациентку

#### **Карточка пациентки (viewPatient)**

**Вкладки:**

1. **Overview (Обзор)**
   - Активные циклы (карточки)
   - Клиническая сводка:
     - Показание (diagnosis)
     - Лечащий врач
     - Дата рождения
     - Контактный телефон
   - История циклов (таблица)
   - Недавняя активность (audit log)

2. **Tests/Docs (Обследования и документы)**
   - Таблица обследований:
     - Дата, тип (АМГ, AFC, FSH и др.), значение, референс
   - Документы цикла (протоколы)
   - Кнопка «Добавить результат»

3. **Cycles (Циклы)**
   - Полная таблица всех циклов пациентки
   - Столбцы: ID, тип, начало, окончание, статус, этап, результат

4. **Prescriptions (Назначения)**
   - Активные назначения (препарат, доза, режим, период)
   - История назначений

5. **Rx History (История назначений)**
   - Полный журнал всех назначений с датами и авторами

6. **History (Журнал событий)**
   - Audit log: все изменения данных пациентки
   - Формат: дата, время, действие, автор

**Действия:**
- Начать новый цикл
- Добавить обследование
- Назначить препарат
- Просмотреть протокол

#### **Цикл ЭКО (viewCycle)**

**Назначение:** Управление клиническим путём одного цикла.

**Структура:**

**Хлебные крошки:**
Пациенты → [ФИО пациентки] → [ID цикла]

**Заголовок цикла:**
- Пациентка (ссылка на карточку)
- ID цикла, дата начала, врач
- Статус (активен / завершён / отменён)
- Тип (fresh / cryo)
- Ссылка на протокол цикла

**Основная зона (clinical-main):**

Разделы отображаются в зависимости от текущего этапа:

1. **Обследования** (stage 0: Подготовка)
   - Таблица: дата, тип, значение, референс
   - Кнопка «Добавить результат»
   - **Дополнительно:** Прогноз ответа яичников (ML-модель) — опционально

2. **Мониторинг стимуляции** (stage 1: Stimulation)
   - Триггер овуляции (если назначен):
     - Дата, время, препарат
     - Статус: запланирован / введён
   - Таблица визитов:
     - Дата, день протокола, фолликулы (слева/справа, размеры), толщина эндометрия, E2, ЛГ, прогестерон
   - График E2 (тренд эстрадиола по дням)
   - Кнопка «Добавить визит», «Записать триггер»

3. **Пункция и оплодотворение** (stage 2: Retrieval)
   - Дата пункции
   - Количество ооцитов
   - Метод оплодотворения (IVF / ICSI / PICSI)
   - Количество оплодотворённых
   - Уведомление, если 0 ооцитов

4. **Эмбрионы** (stage 3: Embryology)
   - Таблица эмбрионов:
     - ID, день развития, стадия, морфология, статус (культивирование / заморожен / перенесён)
   - Кнопка «Групповая оценка», «Заморозить всех», «Запланировать перенос»

5. **Назначения** (все этапы)
   - Активные назначения текущего цикла
   - Ссылка на полную историю назначений

6. **Переносы и исходы** (stage 4-5: Transfer & Outcome)
   - Таблица переносов:
     - ID, дата, эмбрионы (ID), ХГЧ (значение, дата), клиническая беременность, исход
   - Кнопка «Записать исход»

**Боковая панель (workflow-rail):**

- **Следующее действие:**
  - Заголовок (например, «Записать визит», «Назначить триггер»)
  - Описание
  - Кнопка действия
  - Заметка: «Решение принимает врач»

- **Записанный контекст:**
  - АМГ / AFC
  - Последний визит
  - Количество ооцитов
  - Оплодотворено
  - Эмбрионы

- **Клинический путь (journey):**
  - Список из 6 этапов (0-5) или 2 этапов (4-5) для крио-цикла
  - Визуальный индикатор:
     - Галочка — этап завершён
     - Текущий номер — текущий этап
     - Номер — предстоящий этап
     - X — пропущенный этап

**Дополнительные действия (details):**
- Добавить визит
- Записать триггер
- Записать пункцию
- Групповая оценка эмбрионов
- Заморозить всех
- Запланировать перенос
- Отменить цикл

## 3. Клинический путь цикла ЭКО

### 3.1. Этапы (stages)

| Этап | Код | Название | Описание | Ответственный |
|------|-----|----------|----------|---------------|
| 0 | `preparation` | Подготовка | Обследования, анализы, прогноз ответа | Репродуктолог |
| 1 | `stimulation` | Стимуляция | Протокол стимуляции, мониторинг, триггер | Репродуктолог |
| 2 | `retrieval` | Пункция | Забор ооцитов, оплодотворение | Репродуктолог + Эмбриолог |
| 3 | `embryology` | Эмбриология | Культивирование, оценка эмбрионов | Эмбриолог |
| 4 | `transfer` | Перенос | Перенос эмбрионов в полость матки | Репродуктолог |
| 5 | `outcome` | Исход | ХГЧ, клиническая беременность, роды | Репродуктолог |

### 3.2. Переходы между этапами

**Fresh cycle (свежий цикл):** 0 → 1 → 2 → 3 → 4 → 5
**Cryo cycle (крио-цикл):** 4 → 5 (эмбрионы из предыдущего цикла)

### 3.3. Данные на каждом этапе

**Stage 0: Подготовка**
- Обследования (investigations):
  - АМГ (amh_ng_ml) — антимюллеров гормон, нг/мл
  - AFC (afc) — количество антральных фолликулов
  - FSH, LH, эстрадиол и др.
- Прогноз ответа яичников (ML-модель):
  - Вход: АМГ, AFC
  - Выход: категория ответа (low / normal / high), вероятность

**Stage 1: Стимуляция**
- Протокол стимуляции:
  - Тип (agonist / antagonist / short / long / ultra_long / natural)
  - Препараты и дозы по дням
  - План vs факт
- Визиты (visits):
  - Дата, день протокола
  - Фолликулы: количество слева/справа, размеры (массив)
  - Толщина эндометрия (мм)
  - Эстрадиол (E2, пг/мл)
  - ЛГ, прогестерон (опционально)
  - Заметки УЗИ
- Триггер овуляции (trigger):
  - Дата, время
  - Препарат (ХГЧ / агонист ГнРГ)
  - Статус (запланирован / введён)

**Stage 2: Пункция (retrieval)**
- Дата пункции
- Количество ооцитов (общее)
- Метод оплодотворения (IVF / ICSI / PICSI)
- Количество оплодотворённых
- Время проверки оплодотворения

**Stage 3: Эмбриология**
- Эмбрионы (embryos):
  - ID эмбриона
  - День развития (1-6)
  - Стадия (зигота, 2-клеточный, 4-клеточный, 8-клеточный, морула, бластоциста)
  - Морфология (например, «4AA» для бластоцисты)
  - Количество клеток
  - % фрагментации
  - Статус (культивирование / заморожен / перенесён / утилизирован / остановлен)
  - История оценок (массив: дата, стадия, морфология, автор, подтверждено)
- Time-lapse (recordings):
  - Видео URL
  - События (events):
    - Тип события (tPNa, tPNf, t2, t3, t4, t8, tM, tSB, tB, tEB)
    - Время события (timestamp в видео)
    - Источник (manual / ml_model)
  - ML-оценка:
    - Балл (0-100)
    - Категория (good / fair / poor)
    - Версия модели
    - Дата прогноза
- Крио-хранение (freeze):
  - Метод (витрификация / медленная заморозка)
  - Дата заморозки
  - Место хранения (танк, канистра, позиция, номер соломинки)

**Stage 4: Перенос (transfer)**
- ID переноса
- Дата
- Тип (fresh / frozen)
- Эмбрионы (ID эмбрионов, массив)
- Количество перенесённых
- Толщина эндометрия (мм)
- Сложность переноса (easy / moderate / difficult)
- Тип катетера
- УЗИ-контроль (да / нет)

**Stage 5: Исход (outcome)**
- ХГЧ (hcg):
  - Дата теста
  - Значение (мМЕ/мл)
  - Результат (positive / negative / biochemical)
- Клиническая беременность (cp):
  - Дата УЗИ
  - Визуализация плодного яйца (да / нет)
  - Сердцебиение (да / нет, дата)
  - Количество плодных яиц
- Исход (outcome):
  - Продолжающаяся беременность (ongoing)
  - Не беременна (notPregnant)
  - Потеря беременности (pregnancyLoss)
  - Роды (live_birth):
    - Дата родов
    - Количество детей

## 4. Роли пользователей

### 4.1. Репродуктолог (reproductologist)

**Иконка:** Stethoscope
**Цвет:** Teal (#32776f)

**Доступ:**
- Все этапы цикла
- Назначение обследований
- Протокол стимуляции
- Триггер овуляции
- Пункция
- Перенос
- Исход

**Задачи:**
- Добавить визит
- Назначить триггер
- Записать пункцию
- Запланировать перенос
- Записать исход

### 4.2. Эмбриолог (embryologist)

**Иконка:** Microscope
**Цвет:** Teal (#32776f)

**Доступ:**
- Этап эмбриологии (stage 3)
- Оценка эмбрионов
- Time-lapse анализ
- Крио-хранение

**Задачи:**
- Оценить эмбрионы
- Групповая оценка
- Заморозить эмбрионы
- Импортировать time-lapse
- Запустить ML-оценку

**Отличия от репродуктолога:**
- Фокус на лабораторных задачах
- Не назначает лечение
- Не управляет стимуляцией
- Специализируется на эмбрионах

### 6.1. Прогноз овариального ответа (Ovarian Response Prediction)

**Расположение:** Карточка цикла, этап «Подготовка» (stage 0), опциональный раздел

**Назначение:** Прогнозирование ответа яичников на стимуляцию

**Входные данные:**
- АМГ (amh_ng_ml) — антимюллеров гормон, нг/мл
- AFC (afc) — количество антральных фолликулов

**Выходные данные (response):**
- `category` — категория ответа:
  - `'low'` — низкий ответ
  - `'normal'` — нормальный ответ
  - `'high'` — высокий ответ (риск гиперстимуляции)
- `explanation` — объяснение (текст, опционально)
- `uncertainty` — неопределённость прогноза (текст, опционально)
- `limitations` — массив ограничений модели (текст[])
- `modelId` — ID модели (например, `'ovarian-response-v1'`)
- `modelVersion` — версия модели (например, `'1.0.2'`)
- `predictedAt` — timestamp прогноза
- `durationMs` — время выполнения запроса (мс)
- `source` — источник: `'demo'` | `'real'`

**Режимы работы (настройки):**
- `'off'` — модель выключена
- `'demo'` — демо-режим (локальная имитация)
- `'api'` — реальный API

**Формат запроса (API v1.0):**

```json
POST /api/v1/ml/ovarian-response
Content-Type: application/json

{
  "amh_ng_ml": 2.5,
  "afc": 12
}
```

**Формат ответа (успех):**

```json
{
  "category": "normal",
  "explanation": "Прогнозируется нормальный ответ на стимуляцию (8-15 ооцитов).",
  "uncertainty": "Модель может ошибаться при АМГ < 1.0 нг/мл",
  "limitations": [
    "Модель обучена на европейской популяции",
    "Не учитывает предыдущие циклы"
  ],
  "modelId": "ovarian-response-v1",
  "modelVersion": "1.0.2",
  "predictedAt": "2024-11-03T10:30:00Z",
  "durationMs": 245
}
```

**Формат ответа (ошибка):**

```json
{
  "error": "insufficient_data",
  "message": "АМГ или AFC не указаны"
}
```

**UI элементы:**
- Отображение входных данных (АМГ, AFC)
- Кнопка «Запустить модель»
- Индикатор загрузки
- Badge с режимом («демо» / «реальная модель»)
- Результат: категория (выделена), объяснение
- Метаданные: ID модели, версия, дата, время выполнения
- Предупреждение о «устаревших данных» (если входные данные изменились)
- Кнопка «Отметить как проверенное»

### 7.4. Аналитика: Эффективность клиники

**Назначение:** Статистика и отчёты по эффективности циклов

**Показатели:**
- % оплодотворения = (оплодотворённые ооциты / всего ооцитов) × 100
- Выход бластоцист = (бластоцисты / оплодотворённые) × 100
- % беременности на перенос = (положительные ХГЧ / переносы) × 100
- % клинической беременности = (клинические беременности / переносы) × 100

**Разрезы (фильтры):**
- По врачу (reproductologist)
- По протоколу стимуляции (agonist / antagonist / natural)
- По возрасту пациентки (< 30, 30-35, 35-40, > 40)
- По донору (донорские ооциты / собственные)
- По периоду (месяц, квартал, год, произвольный период)

**Полная история пациентки:**
- Все циклы (таблица)
- График: % оплодотворения по циклам
- График: количество ооцитов по циклам
- Сравнение протоколов (если пациентка проходила разные)

## 9. Дополнительные замечания

### 9.1. Отличия демо от продакшена

**В демо:**
- Данные хранятся в localStorage браузера
- ML-модели работают в демо-режиме (локальная имитация)
- Нет реальной авторизации (выбор роли в UI)
- Нет интеграции с внешними системами

**В продакшене (наш бэкенд):**
- PostgreSQL в Docker
- JWT-авторизация с ролями
- Реальные ML-модели по API
- Audit log всех изменений
- Soft delete (физическое удаление запрещено)

### 9.2. Терминология

**Русский → Английский:**
- Пациентка → Patient
- Цикл → Cycle
- Визит → Visit
- Пункция → Retrieval
- Ооцит → Oocyte
- Эмбрион → Embryo
- Перенос → Transfer
- Исход → Outcome
- Назначение → Prescription
- Обследование → Investigation

### 9.3. Обезличивание данных

**Обязательно:**
- ФИО → анонимный ID (medical_record_number)
- Контакты → не хранятся
- Адрес → не хранится

**Хранятся:**
- Дата рождения (для расчёта возраста)
- Медицинские показатели
- Результаты анализов
- История циклов
