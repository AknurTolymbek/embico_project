# EMBICO — Frontend

React + TypeScript + Vite, Ant Design и TanStack Query.

## Запуск

```bash
npm ci
npm run dev
```

Бэкенд должен быть доступен на `http://localhost:8000`. Без `VITE_API_URL` запросы `/api` идут через прокси Vite; это позволяет использовать локальный фронтенд на другом порту без изменения CORS бэкенда.

В Docker Compose прокси использует `API_PROXY_TARGET=http://backend:8000`, а `VITE_API_URL` оставлен пустым. Открывайте `http://localhost:5173/patients` или `http://127.0.0.1:5173/patients`. После изменения переменных пересоздайте сервисы: `docker compose up -d --build backend frontend` (либо `docker-compose`, если Compose установлен отдельной командой).

Для отдельного API задайте `VITE_API_URL` перед запуском или сборкой. При размещении production-сборки без этой переменной веб-сервер должен перенаправлять `/api` на бэкенд и обслуживать маршруты React через `index.html`.

```bash
npm run build
npm run lint
```

## Страницы

- `/patients` — реестр, поиск по номеру карты или ID, фильтры заполненности, сортировка, пагинация и экспорт отфильтрованных данных в CSV.
- `/patients/:id` — карточка пациента, медицинские показатели, даты создания и обновления, индикатор заполненности.
- `/patients/:id/predict` — запуск ML из кнопки «Предикт» в карточке: фото бластоцисты или time-lapse (кадры F0, время каждого кадра, дополнительные плоскости F−15/F+15).

ML-форма отправляет файлы в `multipart/form-data` на существующие `/api/v1/ml/blastocyst/predict` и `/api/v1/ml/timelapse/predict`. Перед запуском проверяется `/api/v1/ml/status`. Ответ показывает оценки, уверенность, морфокинетику, предупреждения и доступен для скачивания в JSON; в базу результатов API сейчас не сохраняет. Для реального расчёта нужны веса в `ml-model/weights` и сборка бэкенда с `INSTALL_ML=true`. Интерфейс не подменяет отсутствующую модель тестовыми ответами.

Добавление и редактирование открываются в модальных окнах. Совместимые адреса `/patients/new` и `/patients/:id/edit` также открывают соответствующую форму. Главная страница ведёт в реестр.

Интерфейс использует реальные поля `backend/app/schemas/patient.py`: обезличенный номер карты, дата рождения, группа крови, рост, вес и АМГ. ФИО и сведения о циклах API пациентов сейчас не предоставляет. История карты показывает только даты создания и последнего обновления, а не журнал отдельных изменений.

Реестр получает массивы пациентов порциями через `/api/v1/patients/`. Поиск, сортировка и пагинация выполняются на клиенте, поскольку текущий API не поддерживает поиск и не возвращает общее количество записей. При росте базы эти операции стоит перенести на сервер.

Текущий механизм гостевого доступа сохранён. Разделы «Циклы лечения», «Лаборатория» и «Документы» доступны из бокового меню и открывают страницы «В стадии разработки». Остальные существующие маршруты сохранены.
